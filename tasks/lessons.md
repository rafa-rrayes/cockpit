# Lessons

## 2026-11-13: size the process to the change

I planned the roadmap board as "Cockpit 0.2", built by a workflow of four agents. Rafa rejected the plan: "No need
for 0.2, its 0.1.1. Do something yourself, no need for subagents".

- An addition to something that already exists is a patch version (0.1.0 → 0.1.1), even when it is a visible
  feature. A minor version is for a planned release with several things in it.
- A change I can hold in my head (one feature, a dozen files) I write myself, inline. Workflows and subagents are
  for builds with parts that are really independent, or when Rafa asks for them.
- Before proposing a plan, cut it to what was asked. The first plan had branch links, release editing and
  release deletion that nobody asked for; the board shipped without them.
